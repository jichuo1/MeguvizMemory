# ARM64 本地输入 profile

这个工具为独立的 arm64 验证准备一份**本机私有输入清单**。它不会连接设备、启动消费者、运行性能测试或修改现有 v2 采集器。清单只能存放在全新 `build/` 子目录，不要提交、上传、粘贴或公开其中的路径、摘要、来源身份与原始日志。公开记录只应包含脱敏的状态、检查范围与局限。

## 输入合同

固定角色为核心库、核心/C/C++ 三个安全性测试、DEX 正式版和诊断版、图像 paired 与 perf；另绑定同批 DEX A1/A3、DEX 导入及图像压力测试。每个角色固定唯一文件名，记录长度、SHA-256 和 ELF 属性，不允许角色替换或向 bundle 额外添加文件。

工具筛选核心、JNI 与可执行文件的 ELF 类别、字节序、版本、头部长度、AArch64 机器类型和共享/PIE 类型，检查执行文件的 Android 解释器、所解析动态依赖的精确集合，并拒绝运行时搜索路径；校验核心库与候选 SDK、AAR 中的相同核心字节，JNI 在 SDK/AAR 间相同；校验候选包、锁定源码和准备后的 DEX 源码清单、三类测试源码、构建图与核心库链接关系。DEX 正式版与诊断版必须具有不同的预期编译开关。这些是有限字段筛选，不是完整 ABI 检查，也不证明文件可以加载或运行。

输入路径必须在工作区内，构建产物、源码快照、构建图和输出必须在 `build/` 内；读取构建文件时拒绝符号链接、Windows reparse point 和硬链接。SDK 必须等于候选包中的 SDK 文件集。仅允许使用现有构建目录约定及指定的 Android SDK 工具入口；读取入口时拒绝祖先目录中的符号链接或 reparse point，也拒绝入口文件的硬链接；CMake 缓存必须与指定工具链入口一致。已绑定脚本、构建图、已选工具入口和锁定文件发生漂移时校验失败。

## 操作

从项目根目录运行 `python tools/freeze_arm64_input_profile.py freeze --help` 查看所有必填路径。调用者应明确提供同一构建批次的 bundle、SDK、构建根、锁定源码根及其锁、准备好的 DEX 目录及其锁、候选包及脱敏候选证据、postcheck，以及本机 Android SDK 根目录。`--out-dir` 必须是 `build/` 内不存在的目录，其父目录须已存在。使用现有产物时不得覆盖旧输出。

成功时工具写入 `profile.json` 和 `profile.sha256`；两者是私有文件。退出状态为零且完成标记存在，才视为冻结成功；失败残留不可作为有效 profile。验证时调用 `validate --profile <私有 profile 文件> --profile-sha256 <预先可信保存的摘要>`，必须由调用方独立保管预期摘要，不能把同一目录中的摘要当成独立信任根。验证前后重新读取输入并核对身份，发现变化则拒绝。调用链今后接入 profile 时仍须在实际使用前验证并约束输入，且不得与历史证据混用。

本地负例：`python -m unittest discover -s tools -p test_freeze_arm64_input_profile.py -v`。

## 独立功能验证入口

`tools/validate_arm64_consumers_profile_v2.py` 要求同时显式提供 `--input-profile` 和从独立可信位置取得的 `--input-profile-sha256`。设备仍须满足现有所有权释放、空闲、输入及环境合同；提供 profile 本身不授权设备使用。该入口的输出只能放在 `build/` 内全新目录，整份功能收据、暂存清单、命令和本机缓存均属私有，不可上传或公开原始路径、摘要、设备标识或日志。

入口在首个 ADB 命令前、部署前后、核心安全用例后、各用例组之间和最后一个 ADB 命令后重新核对 profile、其角色、SDK 和源码；功能入口自己的选定依赖脚本从本轮开始也作阶段性防漂移核对。每个文件推送前后再核对本地身份，并比对设备侧摘要。这里是**阶段检查而非持续监控**，仍存在检查与使用之间的时间窗口；输出上限或空闲信息不完整会终止本轮。输出超限会立即尝试停止本地 ADB 传输，等待退出的时间有上限，并丢弃异常输出；不能确认本地进程退出时标为未知。无论本地传输是否退出，设备侧子进程状态均不能推定，工具不会自动终止设备进程或重试。

若系统管道长期不返回，本地读取线程也可能暂留；这不改变设备侧状态未知的判定。

该入口为功能收据使用独立 scope，旧性能冻结器不接受它；profile 当前没有接入性能冻结。真实 DEX 与生成的图像输入仍按原有功能合同检查，后续性能实验必须单独冻结这些输入和采集协议。

## 边界

- 这是同权限本机的完整性检查，不是签名、可信构建证明、运行时映射字节证明或并发环境下的设备锁。不能阻止有同权限的进程替换全部输入及其可信摘要，也不能消除校验后替换的时间窗口。
- 选定工具入口的身份从冻结时起绑定；历史构建时的工具身份没有独立证明。NDK 其他文件、系统库、完整 sysroot、Python 运行环境及所有构建环境变量没有完全封存，不能据此声称整个工具链无漂移。
- 当前 profile 未冻结真实测试 DEX、图像数据、设备状态、采集器/配对协议和负载运行参数；这些必须在新的独立实验协议中另行绑定。不得将本清单直接称为功能、设备、生命周期、性能或 BIL 接入通过。
